# План перевода ЭСForms на Blazor (.NET 7)

## 1. Цель и границы

Заменить WinForms-приложение `UIExpertSystem/ЭСForms` новым веб-приложением `EsUi` на Blazor Server (.NET 7), сохранив все бизнес-функции настройки ЭС и запуска консультации.

Что важно:

- новый UI не использует `ClassicClasses`, `EsStorageAdapter`, `ExpertSystemDb` и `Logic` (net48);
- новый UI работает напрямую с EF Core-моделями;
- настройки ЭС хранятся в новой БД `EsDb` (модель `EsDb`), фильмы и советы — в существующей `FilmsDb` (модель `FilmDb`);
- старый `ЭСForms` после проверки убирается из решения (файлы можно оставить как архив — уточняется при согласовании);
- ветка реализации: `feature/es-ui-2`, от текущего `master`, без push;
- содержимое ветки `feature/es-ui` не используется.

## 2. Выбранное решение

### 2.1. Новые проекты

| Проект | Назначение | Аналогия |
|---|---|---|
| `EsUi` | Blazor Server UI для настройки ЭС и консультации | `FilmsUi` |
| `EsServices` | View-модели, конвертеры, валидация, сервисы настройки ЭС, движок консультации, работа с советами и фильмами | `FilmsServices` |

`EsServices` ссылается на `EsDb`, `FilmDb`, `CommonRepositories`.
`EsUi` ссылается на `EsServices`, `EsDb`, `FilmDb`.

### 2.2. Почему не тянем старые проекты

`Logic` и `ExpertSystemDb` — .NET Framework 4.8 + EF6, их нельзя подключить к net7. Переносить `Logic` целиком в рамках этой задачи не нужно: из него переносится только то, что нужно UI ЭС:

- алгоритм консультации (`EsLogic`, `EsAlgorithm`, `EsAlgorithmForFilms`);
- подбор фильма по совету/фильтрам (`FilmAndAdviceLogic`);
- синхронизация советов в домен `#Советы` (`СинхронизацияБдФильмовСБзЭс`);
- отображение значений домена `#Советы`.

Всё это реализуется заново в `EsServices` на EF Core 7 и `EsDb`/`FilmDb`.

### 2.3. База данных

Рекомендуемый вариант:

- новая БД `EsDb` (SQL Server, локально `(local)`);
- схема создаётся EF Core-миграцией проекта `EsDb`;
- данные настроек ЭС переносятся SQL-скриптом из `ExpertSystemDB`;
- фильмы и советы не переносим: `FilmsDb` уже содержит те же 21 663 фильма и 36 советов, что и `ExpertSystemDB` (проверено по локальным базам).

Почему не подключаем `EsDb` к старой `ExpertSystemDB` напрямую:

- это оставляет старую схему (`*Set`, старые FK-колонки) и не выполняет заявленную в README замену `ExpertSystemDb`;
- новая модель требует явных FK и nullable-полей, которых в старой схеме нет;
- старую БД можно оставить как архив консультаций.

### 2.4. Семантика сохранения

Рекомендуется сохранять изменения **новой версией ЭС**, как это делает старый `ExpertSystemStorageAdapter`:

1. текущая версия переименовывается в `<Имя>_auto_<yyyy-MM-dd-HH-mm-ss>`;
2. из отредактированного графа создаётся новая ЭС с прежним именем;
3. старые консультации остаются привязанными к старой версии и не ломаются.

Плюсы: сохраняется история консультаций, не нужно удалять/переписывать правила, на которые есть ссылки.
Минусы: в БД накапливаются версии; список ЭС нужно показывать с пометкой версии.

Альтернатива — редактирование «в той же записи». Проще, но при удалении правил/переменных будут падать FK старых консультаций либо придётся удалять историю. Поэтому по умолчанию выбираем версионирование.

### 2.5. Аутентификация

Согласовано: добавляем Identity по образцу `FilmsUi` (отдельная БД `aspnet-EsUi-identity`). Все страницы, кроме логина/регистрации, закрываем авторизацией.

## 4. Модель данных и миграции

### 4.1. Доработка `EsDb`

В `EsDb` уже есть нужные сущности (`ExpertSystem`, `Domain`, `DomainValue`, `Variable`, `Fact`, `Rule`, `RuleFact`, `Consultation`, `ConsultationFact`, `ConsultationRule`, `GoalStack`, `FinalSolution`, `Session`, `Review`), но модель «сырая». Нужно:

- добавить явные FK-свойства (`ExpertSystemId`, `DomainId`, `VariableId`, `RuleId`, `FactId`, `ResultId`, `TargetId` и т.д.);
- исправить nullable-аннотации: `Target?`, `Rule.Result?`, `Variable.Domain?`, `Fact.DomainValue?` — иначе EF сделает обязательными поля, которые старый UI допускал пустыми (новая ЭС без цели, правило без вывода, переменная без домена);
- настроить связи в `EsDbContext.OnModelCreating` и `DeleteBehavior` (конфигурационные дочерние — cascade; ссылки из консультаций — restrict, чтобы не терять историю);
- добавить индексы по именам/связям (без жёстких unique-констрейнтов, чтобы не ломать импорт);
- добавить `EsDbContextFactory`/строку подключения для `dotnet ef`.

### 4.2. Миграция схемы

- добавить в `EsDb` пакеты `Microsoft.EntityFrameworkCore.Design`/`Tools` (Design — в `EsDb`, Tools/Design — в `EsUi` как startup);
- создать миграцию `InitialCreate`;
- применить её к новой БД `EsDb`.

Команды (выполняются после согласования, при необходимости — пользователем):

```powershell
dotnet ef migrations add InitialCreate --project EsDb --startup-project EsUi
dotnet ef database update --project EsDb --startup-project EsUi
```

### 4.3. Перенос данных из `ExpertSystemDB`

Скрипт: `EsDb/Migrations/Data/ImportFromExpertSystemDB.sql`.

Переносим только настройки ЭС (обе существующие версии, включая `Фильмы`):

| Старая таблица | Новая таблица | Особенности |
|---|---|---|
| `ExpertSystemSet` | `ExpertSystems` | `TargetId` заполняется позже из `VariableSet.ExpertSystemVariable1_Variable_Id` |
| `DomainSet` | `Domains` | `ExpertSystemId` = `ExpertSystemDomain_Domain_Id` |
| `DomainValueSet` | `DomainValues` | `DomainId` = `DomainDomainValue_DomainValue_Id` |
| `VariableSet` | `Variables` | `DomainId` = `Domain_Id`, `ExpertSystemId` = `ExpertSystemVariable_Variable_Id` |
| `FactSet` | `Facts` | `VariableId`, `DomainValueId` |
| `RuleSet` | `Rules` | `ResultId`, `ExpertSystemId` |
| `RuleFactSet` | `RuleFacts` | `RuleId`, `FactId`, `Order` |

Старые консультации, сессии и `GoalStack` **не переносим** в первую версию: они остаются в `ExpertSystemDB` как архив. Новые консультации пишутся в `EsDb`. Это нужно явно зафиксировать в `impl.md`.

Скрипт делает проверку «новая БД пуста», использует транзакцию и `IDENTITY_INSERT`, после импорта выставляет `IDENTITY`-счётчики.

### 4.4. Строки подключения

`EsUi/appsettings.json`:

```json
"ConnectionStrings": {
  "EsConnection": "data source=(local);initial catalog=EsDb;TrustServerCertificate=true;integrated security=True;MultipleActiveResultSets=True;App=EntityFramework",
```

## 5. Структура `EsServices`

```text
EsServices/
  ViewModel/
    Common/BaseViewModel.cs
    ExpertSystemVM.cs
    DomainVM.cs
    DomainValueVM.cs
    VariableVM.cs
    FactVM.cs
    RuleVM.cs
    RuleFactVM.cs
    Consultation/...
  Converters/
    ExpertSystemConverter.cs
  Validators/
    ExpertSystemValidator.cs
  Services/
    IExpertSystemService.cs / ExpertSystemService.cs
    IAdviceCatalogService.cs / AdviceCatalogService.cs
    IAdviceSyncService.cs / AdviceSyncService.cs
    Consultation/
      ConsultationEngine.cs
      IConsultationService.cs / ConsultationService.cs
      ConsultationFlowState.cs
      IFilmRecommendationService.cs / FilmRecommendationService.cs
  DTOs/
```

Ключевые решения:

- `ExpertSystemVM` — агрегат: домены, переменные, правила, цель; редактируется в памяти, сохраняется целиком.
- `FactVM` переиспользуется правилами (как и старые `Fact`), чтобы одинаковые «переменная = значение» не дублировались.
- `DomainValueVM.Display` показывает GUID совета как читаемый текст; резолвится через `IAdviceCatalogService`.
- `ExpertSystemService.LoadAsync(id)` загружает граф одним `AsSplitQuery()`-запросом с Include.
- `ExpertSystemService.SaveAsNewVersionAsync(vm)` переименовывает текущую версию и создаёт новую со всеми дочерними сущностями.
- `ExpertSystemValidator` проверяет: имена, дубли, домены/значения, тип переменной, цель, правила (посылки, вывод, допустимость значения), отсутствие «запрашиваемой» переменной в выводе.
- При удалении переменной: убираем её из выводов и посылок; правила без посылок удаляем (как в старом UI).
- При смене типа на «запрашиваемая»: очищаем выводы правил (как в старом UI).
- При удалении домена: у переменных очищается домен; валидатор предупреждает о правилах, которые из-за этого стали невалидными.

## 6. Движок консультации

### 6.1. Общий движок

`ConsultationEngine` — чистый in-memory алгоритм над `ExpertSystemVM`, без EF и без `ClassicClasses`:

- стек целей, доказанные факты, сработавшие правила;
- поиск правил по цели, сортировка по `Order`;
- запрос значения у пользователя для `Queried`;
- для `DeductionQueried` — сначала пробуем все правила, и только потом спрашиваем (исправляем известную неточность старого алгоритма);
- защита от циклов и ограничение глубины;
- результат: вопрос, итоговый факт или «не удалось вывести»;
- объяснение: сработавшие правила (ЕСЛИ / ТО / ТАК КАК) и установленные факты.

`ConsultationService`:

- загружает актуальную версию ЭС;
- создаёт `Session`/`Consultation` и хранит состояние консультации в scoped-сервисе (в рамках Blazor-цепочки);
- по завершении сохраняет в `EsDb` итоговую консультацию, факты, сработавшие правила и `FinalSolution` (для истории/объяснения).

### 6.2. Сценарий для фильмов

Если ЭС называется `Фильмы` (константа, как в старом коде), перед общим движком включается film-сценарий:

1. «Вы примерно знаете, что хотите посмотреть?»
2. Если да — выбор жанров/тегов (в памяти, без новых таблиц), затем подбор фильма.
3. Если нет — запуск общего движка ЭС, результат — GUID совета.
4. По результату:
   - GUID совета → порт `FindFilmsByAdvice` (вектор свойств, фильтрация знаков, расстояние, топ-25%, случайная пятёрка, случайный фильм);
   - фильтр по жанрам → порт `FindFilmsByFilters`;
   - нет фильмов → понятное сообщение.
5. Карточка фильма: постер, название, год, рейтинг, описание, жанры, страны, актёры, режиссёры, теги, ссылки.

Случайный выбор переписываем без старого `TakeRandom` (там потенциальные зацикливания и смещение) — через корректный shuffle.

## 7. UI `EsUi`

Blazor Server, bootstrap-вёрстка и layout по образцу `FilmsUi`, свои статические файлы в `wwwroot`.

Страницы:

- `/` — домашняя/краткая справка;
- `/expert-systems` — список ЭС: имя, версия (`auto`), количество доменов/переменных/правил, кнопки «Открыть», «Создать»;
- `/expert-systems/{id}` — редактор ЭС с вкладками:
  - «Домены» — список доменов и значений, добавление/переименование/удаление, порядок, читаемые советы;
  - «Переменные» — список и форма: имя, домен, тип, вопрос, объяснение; добавление/удаление/переименование/порядок; быстрые действия «добавить домен/значение»;
  - «Правила» — список, форма, посылки, вывод, объяснение, порядок; проверки и читаемые факты;
  - «Цель» — выбор целевой переменной;
  - «Синхронизация» — добавить недостающие советы `FilmsDb` в `#Советы`;
  - «Сохранить» / «Отменить» — версионное сохранение и сброс.
- `/expert-systems/{id}/consultation` — мастер консультации и результат;
- `/consultations/{id}/explain` — объяснение сохранённой консультации (дерево ЕСЛИ/ТО/ТАК КАК + установленные факты).

Компоненты:

- `DomainEditor.razor`, `VariableEditor.razor`, `RuleEditor.razor`, `GoalEditor.razor`;
- `ConsultationWizard.razor`, `FilmResultCard.razor`, `ExplanationTree.razor`;
- `EntityPicker`/`ListEditor` можно упростить относительно `FilmsUi`, т.к. здесь граф, а не независимые справочники.

Ошибки, загрузка, пустые состояния, подтверждения удаления — обязательны.

- [ ] В консоли/логах нет необработанных исключений.

## 10. Риски и тонкие места

1. **Версионирование**: при каждом сохранении создаётся новая ЭС; список будет содержать `_auto_`-версии. Нужен понятный UI-фильтр/пометка.
2. **Старые консультации**: в новую БД не переносятся; история остаётся в `ExpertSystemDB`. Если нужна миграция истории — отдельный этап.
3. **`DeductionQueried`**: старое поведение спрашивало слишком рано; исправляем на «сначала все правила, потом вопрос». Это осознанное отличие, фиксируем в `impl.md`.
4. **Film pre-flow**: выбранные жанры/теги хранятся в состоянии консультации, а не в отдельных таблицах (в `EsDb` их нет). При перезагрузке страницы консультация начинается заново.
5. **Порядок элементов**: в старой схеме порядок доменов/переменных/значений неявно задавался Id. В новой версии порядок сохраняется порядком вставки при версионном сохранении; для посылок есть явный `Order`.
6. **`#Советы`**: в старом домене 49 значений, в `FilmsDb` 36 советов; синхронизация добавит недостающие.
7. **Удаление ЭС** в старом UI отсутствовало; в новом по умолчанию тоже не делаем (только архивные версии).
8. **Identity** добавляется по образцу `FilmsUi`; нужна отдельная БД идентичности и её миграция.
9. **SQL-скрипт импорта** выполняет пользователь по инструкции до проверки данных.
10. **Старые проекты**: проект `ЭСForms` удаляется полностью; `ClassicClasses` ещё используется в `Logic`/`FilmForms`, поэтому его полное удаление — отдельный рефакторинг, не входит в эту задачу.

## 11. Согласованные решения

1. Сохранение — новой версией.
2. База настроек — новая `EsDb` + импорт данных из `ExpertSystemDB`.
3. Аутентификация — Identity, как в `FilmsUi`.
4. Старый `ЭСForms` — удалить проект полностью.
5. Консультация — полный сценарий фильмов: жанры/теги + ЭС.
6. Миграцию данных выполняет пользователь по подготовленной инструкции.

## 12. Ожидаемый результат

Новый `EsUi` на Blazor Server (.NET 7), который без WinForms/ClassicClasses позволяет:

- создавать и открывать ЭС;
- редактировать домены, значения, переменные, правила и цель;
- синхронизировать советы из `FilmsDb`;
- сохранять новую версию ЭС;
- запускать консультацию и получать фильм;
- смотреть объяснение консультации;
- работать с реальными данными «Фильмы» из `EsDb` + `FilmsDb`.
