# План переноса функций FilmForms в FilmsUi

## 1. Цель и границы

Перенести в `FilmsUi` (Blazor Server, .NET 7) функции старого WinForms-проекта `FilmForms`, которых там сейчас нет:

- редактирование справочников: актёры, жанры, режиссёры (сущность `Producer`), страны, пользовательские свойства (теги);
- редактирование советов (`Advice`): список, создание, изменение, удаление, привязка фильмов и тегов со значениями;
- загрузка фильма по ссылке с Кинопоиска (аналог `frmFillFilmFromUrl`) отдельным пунктом меню.

По итогам уточнений:

- загрузку с Кинопоиска делаем переносом старого HTML-парсера по ссылке;
- дополнительно не берём: массовую загрузку HTML-файлов, Excel-выгрузку/загрузку тегов, отдельное создание/удаление фильма в UI, синхронизацию с ЭС (в старом приложении она уже удалена).

База данных: **изменений схемы и миграций нет**. Меняются только код и UI.

## 2. Что переносим

| Старое (FilmForms) | Новое (FilmsUi) |
|---|---|
| `frmActorList` + `frmActorEdit` | страница `/actors`, общий компонент списка справочника |
| `frmGenreList` + `frmGenreEdit` | страница `/genres` |
| `frmProducerList` + `frmProducerEdit` | страница `/producers` |
| `frmCountryList` + `frmCountryEdit` | страница `/countries` |
| `frmCustomPropertyList` + `frmCustomPropertyEdit` | страница `/customproperties` |
| `frmAdviceList` | страница `/advices` |
| `frmAdviceEdit`, `frmAdviceFilmEdit`, `frmAdviceCustomPropertyEdit` | страница `/adviceedit/{id}` (id = 0 — новый совет) |
| `BaseListForm` (добавить/изменить/удалить) | общий компонент `DictionaryList<TEntity>` |
| `frmFillFilmFromUrl` | страница `/fillfilm` + пункт меню «Заполнить фильм» |
| меню `frmMain` | обновлённое `NavMenu.razor` |

## 3. Изменения в логике

### 3.1. Общая инфраструктура справочников

Создать:

- `CommonRepositories/NamedRepository.cs` — `INamedRepository<T>` и `NamedRepository<T>`:
  - сортировка по `Name` вместо `Id`;
  - серверный поиск `SearchByNameAsync(query, limit, page)` и `GetCountByNameAsync(query)`.
- `FilmsServices/ViewModel/Common/INamedViewModel.cs` — интерфейс с `string Name { get; set; }` для общих страниц справочников.
- `FilmsServices/Services/Common/NamedService.cs` — `INamedService<VM>` и `NamedService<DB, VM>`:
  - наследует `BaseSevice<DB, VM>`;
  - добавляет поиск по имени.

Изменить:

- `ActorVM`, `GenreVM`, `CountryVM`, `ProducerVM`, `CustomPropertyVM` — реализовать `INamedViewModel`.

Зачем: один универсальный экран списка с сортировкой, поиском, постраничным выводом и CRUD для пяти справочников, без загрузки всех 45 000 актёров в браузер.

### 3.2. Советы

Изменить `FilmsServices/ViewModel/AdviceVM.cs`:

- `Films` становится коллекцией `AdviceFilmVM` (фильм + значение), а не просто `FilmVM`;
- добавить вычисляемые `FilmsStr` и `TagStr` — как в старом `AdviceExtension` (для колонок списка советов);
- в конструкторе задавать новый `Key = Guid.NewGuid()`.

Создать `FilmsServices/ViewModel/AdviceFilmVM.cs`:

- `Film` (`FilmVM`), `Value`, `Name`, `FilmId`.

Изменить `FilmsServices/Converters/AdviceConverter.cs`:

- исправить существующие `TODO`: сохранять и читать `AdviceFilm.Value`;
- при сохранении обновлять значение у существующей связи, добавлять новые и удалять отсутствующие;
- то же для `AdviceCustomProperty` (там значение уже сохранялось).

Изменить `FilmDb/Model/Advice.cs`:

- в конструкторе задавать `Key = Guid.NewGuid()` (как в старой модели). Схема БД не меняется.

Изменения в `AdviceRepository`:

- сортировка списка советов по `Key` (как в старом списке).

### 3.3. Загрузка фильма с Кинопоиска

Создать в `FilmsServices`:

- `Services/Kinopoisk/KinopoiskHtmlParser.cs` — перенос разбора старой страницы Кинопоиска:
  - постер, название, год, слоган, рейтинг, описание;
  - актёры, страны, режиссёры, жанры;
  - извлечение `KinopoiskId` из URL;
  - безопасный разбор (не падать, если поля нет);
  - дополнительные fallback-и на `og:title`, `og:image`, `og:description` и JSON-LD на случай частичной смены вёрстки.
- `Services/Kinopoisk/KinopoiskFilmImportService.cs` — `IKinopoiskFilmImportService`:
  - загружает HTML по URL;
  - распознаёт антибот-заглушку Кинопоиска (`sso.kinopoisk.ru`, текст про автоматические запросы) и бросает понятную ошибку;
  - проверяет дубль по названию и году;
  - находит или создаёт актёров, страны, жанры, режиссёров;
  - сохраняет фильм со связями и возвращает его Id.
- `Exceptions/KinopoiskBlockedException.cs` — понятная ошибка антибота.
- `Exceptions/FilmAlreadyExistsException.cs` — дубль с Id существующего фильма.

Изменить `FilmsUi/Program.cs`:

- зарегистрировать `HttpClient` (singleton с таймаутом);
- зарегистрировать `IKinopoiskFilmImportService`.

Ограничение (зафиксировано осознанно): Кинопоиск сейчас отдаёт серверным клиентам антибот-страницу, а старая вёрстка изменилась. Парсер переносится как есть с защитными fallback-ами; при блокировке или неузнаваемой странице пользователь получит понятное сообщение, а не падение.

## 4. Изменения в UI

Создать:

- `Shared/DictionaryList.razor` — общий список справочника:
  - постраничный вывод (50 записей), поиск по имени, сортировка по имени;
  - добавление, переименование, удаление с подтверждением;
  - состояния загрузки, пустого списка и ошибок.
- `Pages/ActorList.razor` (`/actors`);
- `Pages/GenreList.razor` (`/genres`);
- `Pages/CountryList.razor` (`/countries`);
- `Pages/ProducerList.razor` (`/producers`);
- `Pages/CustomPropertyList.razor` (`/customproperties`);
- `Pages/AdviceList.razor` (`/advices`) — Key, фильмы, теги, кнопки «Добавить», «Изменить», «Удалить»;
- `Pages/AdviceEdit.razor` (`/adviceedit/{AdviceId:int}`):
  - Key (только чтение);
  - фильмы совета с редактируемым значением, добавление через `EntityPicker<FilmVM>`, удаление;
  - теги совета со значением, через `ListEditor<CustomPropertyVM>`;
  - сохранение, отмена, удаление.
- `Pages/FillFilm.razor` (`/fillfilm`):
  - поле URL, кнопка «Загрузить фильм»;
  - сообщения об антиботе, дубле (со ссылкой на существующий фильм) и ошибках разбора;
  - при успехе — переход на `/filmedit/{id}`.

Изменить:

- `Shared/NavMenu.razor` — добавить «Справочники» (актёры, жанры, режиссёры, страны, пользовательские свойства), «Советы», «Заполнить фильм».
- `Shared/ListEditor.razor` — необязательный callback после выбора элемента, чтобы новому тегу совета сразу ставить значение 100 (как в старом `frmAdviceCustomPropertyEdit`). Изменение обратно совместимо.
- `README.md` — кратко описать новые страницы и ограничение загрузки с Кинопоиска.

## 6. Как тестировать

1. `dotnet build FilmsUi/FilmsUi.csproj` — без ошибок.
2. Запустить `FilmsUi`, открыть страницы:
   - `/actors`, `/genres`, `/countries`, `/producers`, `/customproperties` — список, поиск, следующая/предыдущая страница;
   - добавить тестовую запись, переименовать, удалить; убедиться, что после удаления список и счётчик обновились;
   - проверить, что удаление связано с фильмами (каскад) и не роняет приложение.
3. `/advices`:
   - открыть существующий совет, изменить значения тегов и фильмов, сохранить, перезагрузить — значения сохранились;
   - создать новый совет, добавить фильм и тег, сохранить, проверить в списке `FilmsStr`/`TagStr`, удалить тестовый совет.
4. `/fillfilm`:
   - пустой URL и некорректный URL — понятная ошибка;
   - реальная ссылка на Кинопоиск — понятное сообщение об антиботе (ожидаемо);
   - разбор старой HTML-страницы проверить на локальном файле/временной консольной проверке парсера (без добавления тестового проекта в репозиторий).
5. Проверить меню и переходы, отсутствие ошибок в консоли браузера.
6. Сверить количество записей в `FilmsDb` до/после ручных тестов; тестовые записи удалить.

## 7. Узкие места и риски

- **Кинопоиск**: антибот и смена вёрстки. Это главный риск; парсер переносится по решению пользователя, но успех на текущем сайте не гарантируется. Ошибка обрабатывается явно.
- **Удаление справочников**: в БД включён каскад, удаление актёра/жанра/страны/режиссёра/тега удалит и связи с фильмами/советами. В UI будет подтверждение с предупреждением.
- **Большие справочники**: 45 529 актёров и 12 657 режиссёров. Поэтому поиск и пагинация делаются на сервере, без выгрузки всей таблицы.
- **Советы**: старый `AdviceConverter` терял `AdviceFilm.Value`. Исправляем; схема БД уже содержит это поле, миграция не нужна.
- **Дубли имён** в справочниках возможны исторически. При импорте с Кинопоиска выбирается первая найденная запись; новых дублей не создаём.
- **Одновременная работа**: Blazor Server + scoped `DbContext`; существующая схема сохраняется, дополнительных фоновых задач нет.
