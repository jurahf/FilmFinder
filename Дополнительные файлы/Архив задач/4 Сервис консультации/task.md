# Задача 4. API консультации: новый сервис EsConsultationServices

## Постановка

В проекте `Logic` есть `EsAlgorithm`, который запускает и проводит консультацию экспертной системы.
В `EsServices` есть аналогичный `ConsultationEngine`, но он работает только в памяти и не сохраняет
промежуточные ответы пользователя.

Предполагается, что в отдельной задаче будет создано API, которое проводит консультации для
множества пользователей одновременно. Сессия должна переживать перезапуск приложения, поэтому
ответы пользователя и состояние консультации должны сохраняться в базу данных `EsDb`.

Нужно создать новый проект `EsConsultationServices` на .NET 7 и реализовать проведение
консультации там. За основу берётся `ConsultationEngine`, но промежуточные ответы сохраняются
в `EsDb`. `EsServices` должен использовать новый сервис в своём коде, а `ConsultationEngine`
из `EsServices` можно удалить.

Шаг «я знаю, что хочу» из старого `Logic` в новом сервисе не реализуется: это UI-сценарий,
а не часть движка консультации.

## Выбранное решение

### 1. Связь проектов

`EsConsultationServices` — самодостаточный проект .NET 7:

- ссылается на `EsDb` и `CommonRepositories`;
- работает с сущностями `EsDb` и собственным доменным движком;
- не ссылается на `EsServices`, чтобы не было циклической зависимости;
- не знает про FilmDb и UI.

`EsServices`:

- сохраняет UI-контракт `IConsultationService` и ViewModel-классы консультации;
- `ConsultationService` становится тонким фасадом, который вызывает
  `EsConsultationServices.IConsultationService` и мапит DTO нового сервиса в существующие ViewModel;
- старый `ConsultationEngine`, `ConsultationEngineState`, `ConsultationSessionState` и
  `ConsultationSessionStore` удаляются.

Отображение значений домена `#Советы` (человекочитаемые описания советов) сохраняется через
интерфейс провайдера отображения, который реализуется в `EsServices` поверх
`IAdviceCatalogService`. Новый сервис без провайдера показывает исходное значение.

### 2. Сохранение состояния

Используется нормализованная схема `EsDb`:

- `Sessions` — сессия, переживающая перезапуск;
- `Consultations` — консультация, ссылка на сессию и экспертную систему;
- `GoalStacks` — стек целей (связный список, верхушка — текущая цель);
- `ConsultationFacts` — доказанные факты и их истинность;
- `ConsultationRules` — сработавшие/проверенные правила;
- `FinalSolutions` — итоговый известный результат;
- новые `ConsultationAnswers` — ответы пользователя (переменная, значение, порядок);
- новые `ConsultationUnknownVariables` — переменные, которые не удалось вывести.

Пустой стек целей означает, что консультация завершена. Если при этом есть `FinalSolution`,
результат известен; если нет — результат не выведен.

Состояние загружается из БД на каждый вызов, поэтому сервис не хранит консультации в памяти
и подходит для одновременной работы множества пользователей. Запись шага выполняется в транзакции.

## Что входит в задачу

1. Создать проект `EsConsultationServices` (.NET 7) и добавить его в решение `EsService/ЭС.sln`.
2. Перенести движок консультации из `EsServices` в новый проект, адаптировав его под доменную
   модель нового проекта.
3. Реализовать в новом проекте сервис консультации:
   - начать консультацию;
   - получить текущий вопрос/результат по `sessionId` (для продолжения после перезапуска);
   - отправить ответ и получить следующий вопрос/результат;
   - получить объяснение.
4. Сохранять и загружать состояние консультации через `EsDb`.
5. Добавить в `EsDb` сущности `ConsultationAnswer` и `ConsultationUnknownVariable`,
   настроить `EsDbContext` и создать миграцию.
6. Перевести `EsServices.ConsultationService` на новый сервис, сохранив существующий UI-контракт.
7. Удалить `ConsultationEngine` и in-memory store из `EsServices`.
8. Обновить `EsUi`: регистрация новых сервисов и провайдера отображения советов.
9. Обновить/добавить тесты:
   - перенести тесты движка;
   - проверить сохранение ответов и продолжение консультации после «перезапуска»
     (новый экземпляр сервиса и `DbContext`).

## Что не входит в задачу

- HTTP API и контроллеры — отдельная задача.
- Удаление проекта `Logic` — отложено по решению пользователя (сейчас `Logic` и `WebApi`
  остаются как есть).
- Удаление `WebApi`, `ExpertSystemDB`, `Utilities.LoadFilms`.
- Перенос шага «я знаю, что хочу» в новый сервис.
- Изменение логики подбора фильма в `FilmsUi`/`EsUi` за пределами сохранения консультации.

## Критерии готовности

- `EsConsultationServices` собирается как .NET 7 проект.
- `EsServices` больше не содержит `ConsultationEngine` и не хранит консультации в памяти.
- Начатая консультация сохраняется в `EsDb`; после создания нового экземпляра сервиса
  (имитация перезапуска) по `sessionId` можно получить текущий вопрос и продолжить.
- Все ответы пользователя сохраняются в `ConsultationAnswers`.
- Итоговый известный результат сохраняется в `FinalSolutions`.
- Существующий сценарий консультации в `EsUi` работает без регрессии, включая отображение
  описаний советов.
- Тесты `EsServices.Tests` проходят.

## Проверка

- `dotnet build EsConsultationServices/EsConsultationServices.csproj`
- `dotnet build EsServices/EsServices.csproj`
- `dotnet build EsUi/EsUi.csproj`
- `dotnet test EsServices.Tests/EsServices.Tests.csproj`
- Миграция `EsDb` применяется к локальной базе `EsDb`.
- Ручной сценарий в `EsUi`: начать консультацию, ответить на вопросы, получить результат;
  проверить строки в `Sessions`, `Consultations`, `ConsultationAnswers`, `FinalSolutions`.

## Замечания

- Полная сборка `EsService/ЭС.sln` через `dotnet build` уже сейчас падает на старых
  `WebApi` и `LoadFilms` из-за отсутствующих VS WebApplication targets и x86-задач.
  Это не регрессия данной задачи; проверять нужно net7-проекты и тесты.
- `Logic` содержит не только консультацию (Excel, Кинопоиск, подбор фильма), но текущие
  net7-проекты его не используют. Удаление отложено до отдельной задачи вместе с `WebApi`.
