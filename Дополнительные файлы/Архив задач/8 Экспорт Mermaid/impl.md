# Реализация: экспорт базы знаний ЭС в Mermaid

Связанная постановка: `task.md`, план: `plan.md`.

## Что сделано

### EsServices

Новый каталог `EsServices/Services/Export/`:

- `ExpertSystemMermaidExporter` — чистый форматтер `ExpertSystemVM -> string`.
  Строит бор (trie) по последовательностям условий правил, затем выводит
  `flowchart TD` с узлами вопросов, ответов и листьев-свойств.
- `IExpertSystemExportService` + `ExpertSystemExportResult` — контракт и результат.
- `ExpertSystemExportService` — находит активную ЭС «Фильмы» через
  `IExpertSystemService.GetListAsync` (точное имя после `Trim`, `OrdinalIgnoreCase`,
  при нескольких — максимальный `Id`), загружает её `GetAsync` и возвращает
  содержимое и имя файла `expert-system-{yyyy-MM-dd}.mmd`.

Узлы:

- вопрос — `Qn["..."]:::question` (прямоугольник);
- ответ — `An(["..."]):::answer` (овал);
- свойство/лист — `Pn{{"..."}}:::property` (шестиугольник);
- битые данные — `Xn{{"..."}}:::invalid` (правило без посылок или без вывода).

Подпись финальной стрелки к листу — `{Order + 1}. {Name}` правила.
Поэтому порядок вывода виден в графе, а имя правила не теряется.

### EsUi

- `Program.cs` — регистрация `ExpertSystemMermaidExporter`,
  `IExpertSystemExportService` и `AddMermaidJS()`.
- `Shared/NavMenu.razor` — пункт «Экспорт» (иконка скачивания).
- `Pages/ExpertSystemExport.razor` — маршрут `/export`: при открытии сразу
  формирует экспорт, показывает имя ЭС, число правил, имя файла и отрисованную
  диаграмму (`MermaidDiagram` из `MermaidJS.Blazor`); кнопка «Скачать .mmd».
- `wwwroot/js/download.js` — сохранение Blob через `DotNetStreamReference`.
- `wwwroot/js/diagram.js` — прокрутка контейнера к середине широкой диаграммы
  после отрисовки (корень дерева находится в центре).
- `Pages/_Host.cshtml` — подключение `js/download.js` и `js/diagram.js`.
- `wwwroot/css/site.css` — стиль `.export-diagram` (прокрутка, рамка).

### Тесты

- `EsServices.Tests/ExpertSystemMermaidExporterTests.cs` — 11 тестов:
  цепочка вопроса/ответа/листа, все варианты ответа домена, цепочка из нескольких
  условий, общий префикс, разные узлы для одного вопроса в разных ветках,
  объединение одинаковых листьев, промежуточный факт, экранирование, правило
  без вывода, правило без посылок, шапка файла.
- `EsServices.Tests/ExpertSystemExportServiceTests.cs` — 4 теста: выбор
  «Фильмы» и игнорирование `_auto_`-версий, имя файла, ошибка при отсутствии ЭС,
  содержимое с подписью листа.

Все 28 тестов `EsServices.Tests` проходят.

## Тонкие места

1. **Контекстные вопросы.** Вопросы и ответы не дедуплицируются глобально:
   ключ узла вопроса — «родительский ответ + имя переменной». Один и тот же
   вопрос, достигнутый по разным веткам, — разные узлы, как в
   `Схема БЗ.graphml`. Общий префикс правил при этом переиспользуется.
2. **Все ответы домена.** Под вопросом создаются все значения домена, включая
   тупиковые. Это соответствует смыслу вопроса, а не набору сработавших правил.
3. **Порядок.** Правила сортируются по `Order`, затем `Name`, затем `Id`;
   условия — по `Condition.Order`, затем `Fact.Id`. Это тот же порядок, в котором
   движок перебирает правила и условия.
4. **Дедупликация листьев и фактов.** Ключ — «имя переменной + значение».
   Одинаковый совет из разных правил — один шестиугольник с несколькими
   входящими стрелками. Если вывод одного правила является условием другого,
   факт становится общим узлом и связывает цепочки.
5. **Экранирование.** `#` заменяется первым, иначе `#quot;` и подобные
   последовательности будут испорчены. Переводы строк — `<br/>`, кавычки —
   `#quot;`, `<`/`>` — `#lt;`/`#gt;`, `&` — `#amp;`.
6. **Битые данные.** Правило без результата или без посылок не роняет экспорт:
   рисуется узел `invalid`. Валидатор такие данные не пропускает, но старые
   записи могут встретиться.
7. **`GetAsync` и описания советов.** Листья получают вектор свойств только
   потому, что `ExpertSystemService.GetAsync` подставляет описания из `FilmsDb`
   через `IAdviceCatalogService`. Если `FilmsDb` недоступна, страница покажет
   ошибку; без описаний в листьях были бы GUID-ы.
8. **Дата.** Один `DateTime.Now` используется и в шапке, и в имени файла, чтобы
   около полуночи они не разошлись.
9. **Только активная ЭС.** Точное имя `Фильмы` отсекает `Фильмы_auto_*`.
   При нескольких точных совпадениях берётся максимальный `Id`.
10. **Консультации не читаются.** Экспорт строится только по `ExpertSystemVM`;
    таблицы консультаций, сессий и оценок не затрагиваются.
11. **Скачивание.** `DotNetStreamReference` — штатный для Blazor Server способ
    без HTTP-контроллера. Файл небольшой, ограничения SignalR не достигаются.
12. **Идентификаторы узлов.** `Q1/A1/P1/X1` — счётчики в порядке обхода,
    а не Id из БД: в тестовых VM Id могут быть нулевыми, а стабильные
    идентификаторы нужны только внутри одного файла.
13. **Отрисовка диаграммы.** `MermaidJS.Blazor` 2.0.1 несёт mermaid 8.13.2
    и грузит её из `_content/MermaidJS.Blazor/...` без CDN. Компонент рисует
    диаграмму в натуральную величину: для отображения добавляется
    `%%{init: {'flowchart': {'useMaxWidth': false}}}%%`, иначе граф шириной
    ~5700 px сжимается под контейнер и становится нечитаемым. Скачиваемый
    `.mmd` этой директивы не содержит. После отрисовки `diagram.js` прокручивает
    контейнер к середине, где находится корень дерева.

## Вопросы и решения, требующие подтверждения

1. **Подпись правила только на финальной стрелке.** Если два правила имеют
   одинаковый путь условий и разные выводы, подписи стоят на разных стрелках
   к своим листьям. Промежуточные стрелки не подписаны, чтобы не дублировать
   одно и то же имя на каждой стрелке цепочки.
2. **Правило без посылок** изображается отдельным узлом, а не отдельной
   диаграммой: в текущих данных таких правил нет, это защита от битых записей.
3. **Формат листа** — `Совет = <вектор>`, как в `FactVM.Display`. Если нужен
   более короткий вид (`<[Совет: ...]>`, как в примере постановки), это
   меняется в одном месте — `ExpertSystemMermaidExporter.GetOrCreateFact`.

  `diagramType: flowchart-v2`, ошибок нет.
- Диаграмма на странице отрисовывается компонентом `MermaidJS.Blazor` 2.0.1
  (внутри — mermaid 8.13.2): видны вопросы, ответы, подписи правил и листья-советы.
- В экспорте 20 вопросов, 26 листьев-свойств, 27 подписанных стрелок правил
